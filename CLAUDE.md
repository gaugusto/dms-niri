# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Personal dotfiles for an Arch Linux desktop running the **niri** Wayland compositor with **DankMaterialShell (DMS)** as the shell/bar/launcher. No build or test suite. Comments and script output are mostly in Portuguese; keep that style.

## Layout: GNU Stow packages

Each top-level directory is a stow package whose contents mirror `$HOME`. For example, `niri/.config/niri/config.kdl` ends up at `~/.config/niri/config.kdl`. On the live machine these are **directory-level symlinks** back into this repo (`~/.config/niri -> ../dms-niri/niri/.config/niri`, and the same for `~/.config/nvim`, `~/.config/dms`, `~/.local/bin`, …). That means editing a file in the repo changes the live config right away, and files that apps write at runtime land in the repo too.

- Deploy a package: `stow <package>` from the repo root (target defaults to `~`).
- Exceptions: `boot/` targets `/` (systemd-boot entry), and `nixos-flake/` is a standalone NixOS flake (`nixosConfigurations.nixos-btw`), not a stow package.
- Bootstrap a fresh system: `01_install_yay.sh` → `02_install_packages.sh` (package list) → `03_ssh_github.sh <email>`.

## niri + DMS config split

- `niri/.config/niri/config.kdl` is the hand-edited config. It ends with `include` lines that pull in `niri/.config/niri/dms/*.kdl`.
- Files under `niri/.config/niri/dms/` are **generated by DMS** (headers say "DO NOT EDIT"). DMS overwrites them when settings change in its GUI. Put custom binds, window rules, and similar in `config.kdl`, not in those files.
- `dms/.config/dms/settings.json` and `plugin_settings.json` are DMS state that the app writes. Expect noisy diffs. Custom themes live in `dms/.config/dms/themes/`.
- DMS features are controlled from niri binds through `dms ipc call <target> <action>` (for example `dms ipc call bar toggle index 0`).
- Validate niri changes with `niri validate`. niri hot-reloads the config when it is saved.

## Other notable pieces

- **zsh**: `zsh/.zshenv` sets `ZDOTDIR=~/.config/zsh`. The real config is split into `zsh/.config/zsh/*.zsh`. Plugins are git-cloned on demand into `zsh/.config/zsh/plugins/` (gitignored) by a small `_zplugin_load` helper in `plugins.zsh`. `zplugin-update` updates them. Prompt is starship.
- **nvim**: uses Neovim's built-in `vim.pack` (0.12+), not lazy.nvim. Each `lua/plugins/<name>.lua` returns `{ "<url>", config = fn }`. A new plugin file must also be added to the `plugins_to_load` list in `lua/config/plugins.lua`. LSP servers are configured per file in `nvim/.config/nvim/lsp/`.
- **scripts**: `scripts/.local/bin/` holds rofi-driven helper scripts (bookmarks, passwords, config picker, dmenus) bound to keys in `config.kdl`. It is on `PATH`.
